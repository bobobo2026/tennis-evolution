# 为什么没有内置击球检测，以及自己实现有多难

本工具的边界是「剪辑」，不是「看懂网球」。这份文档解释这个取舍，并给出如果要自己做检测时的路线。

## 现状：检测可插拔

输入只需要「起止时间 + 可选拍数」：

```text
27:14 - 28:08  Long rally (40 hits)
```

所以任何检测器（商用切片工具、自己的脚本、甚至手点时间轴）都能接进来。剪辑、拼接、角标、自检这四件事
与检测质量解耦，检测升级时整条剪辑流水线不用动。

## 自己实现难在哪

### 第一层：找到「击球声」——不难

球拍击球在音频里是典型的宽带瞬态：起音快、能量集中、频谱宽。常见做法：

1. 提取音频 → 单声道 16 kHz；
2. 计算 onset strength（谱通量 / 高通后的能量包络，`librosa.onset.onset_strength` 一行搞定）；
3. 峰值检测（阈值 + 最小间隔 0.25–0.35 s，因为真实回合里两拍间隔通常 > 0.4 s）。

这一步在安静球场能做到 90%+ 召回。**但它给的是「声音事件」，不是「击球」。**

### 第二层：区分击球 / 落地 / 回声 / 人声——这是难点

同一声「啪」可能来自：

- 球拍击球（你要的）；
- 球落地（能量低、频谱更闷，但室内硬地反弹声很响）；
- 球馆混响拖尾（会让一拍变成两三个峰）；
- 隔壁场地、球童、说话。

可用的区分特征：频谱质心、低频/高频能量比、包络衰减时间、与上一次事件的间隔规律（回合中击球几乎等间隔）。
但每换一个球馆，这些阈值都得重调 —— 这就是为什么它不该硬编码进剪辑工具。

### 第三层：回合聚类与拍数统计——最容易翻车

- 一次回合内的击球间隔通常 0.5–1.5 s；回合之间停顿 3–15 s。用间隔阈值聚类能切出「回合」，
  但捡球、换边、擦汗都会产生假回合。
- **拍数要准，必须逐拍不漏**：漏一拍 `40 hits` 就变 `39 hits`。观众不一定数，但标错了很刺眼。
- 发球、挑高球、失误后的击球会让「间隔规律」失效。

### 现实评估

| 能力 | 难度 | 说明 |
| --- | --- | --- |
| 找到所有声音瞬态 | ★★ | 成熟方法，几十行 |
| 分类击球 vs 落地 | ★★★★ | 需要逐场地校准，或者少量标注数据训练分类器 |
| 回合聚类 | ★★★ | 间隔 + 能量 + 时长规则基本够用 |
| 拍数精度 ≥ 95% | ★★★★★ | 需要真实标注集回归，否则改一个阈值修好一个场地、坏掉另一个 |

结论：做一个「demo 能用」的检测器大约 1–2 天；做一个「公开发布、别人换了球馆也能用」的检测器，
需要标注数据 + 回归测试集，属于独立项目的工作量。因此当前版本选择把检测留在外面。

## 如果要做，建议的分阶段路线

1. **阶段 A（可先合入）**：`detect` 子命令，输出本工具能吃的 JSON。
   onset 检测 + 简单阈值 → 人工过一遍 → 当作「半自动标注器」。价值已经很大：不用手点时间轴。
2. **阶段 B**：加入「回合聚类」，输出 `segments`，拍数用击球计数。用一个球馆的 30 分钟素材做回归集，
   记录每段 P/R。
3. **阶段 C**：把「击球 / 落地」分类器换成小的 CNN（mel 谱输入），并要求跨场地泛化；
   维护一个最小标注集（每段几十秒）作为 CI fixture。
4. **阶段 D**：可选接 LLM/多模态做「精彩度」评分（长回合、制胜分、多拍拉锯），
   但排序策略仍留在 `--sort` 里可覆盖。

在阶段 A 落地前，推荐继续用现成工具生成列表 —— 它们在这件事上比通用脚本更可靠。
